Platform & security

Runs in your environment. Holds none of your data.

Mannjal deploys as a dedicated instance inside your own cloud or data centre. Borrower data never leaves it, and never sits on a Mannjal server.

Four things, answered plainly.

01
Deployment

Your cloud, your tenancy

Each engagement runs as its own instance inside the bank's AWS account or on-premise environment. There is no shared tenancy and no Mannjal-hosted copy of the data.

02
Data isolation

No central store of borrower data

Mannjal never stores or interprets borrower data. Sync between an originator and a lender is bilateral and follows the program's rules, so data moves between the two parties' instances and not through a Mannjal store.

03
Credentials & access

Your keys stay yours

Every integration uses the bank's own API credentials with the providers it already contracts. Mannjal routes and logs the calls; it does not hold or proxy your keys. Access within an instance is role-based with maker-checker controls.

04
Audit logs

One export, not a search

Every action, API call, and document event is timestamped, attributed to a user, immutable, and exportable on demand. An audit of any single loan is one export, not a search across systems.

Integrations

Works with the providers you already use.

KYC, bureau, bank-statement, and e-sign checks run through the service providers the bank already contracts, under the bank's own agreements and credentials. New providers onboard without a system redesign.
